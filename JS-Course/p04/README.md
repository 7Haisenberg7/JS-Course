1. **Что выведет `typeof` для класса и почему?**
   Выведет `'function'`, потому что класс в JavaScript не создаёт новую модель объектов — под капотом это специальная функция-конструктор, работающая поверх прототипов.

2. **Где хранятся методы класса: в каждом экземпляре или в одном месте? Как это проверить?**
   Методы хранятся в одном месте — в свойстве `prototype` самого класса (например, `Product.prototype`), а не копируются в каждый экземпляр. Проверить это можно сравнением методов двух разных экземпляров (`keyboard.describe === mouse.describe` вернёт `true`) или через `Object.getOwnPropertyNames(Product.prototype)`.

3. **Почему метод, сохранённый в переменную, теряет `this`? Как это исправить?**
   Значение `this` определяется в момент вызова и равно объекту слева от точки. При вызове через переменную (`describeFn()`) слева от скобок объекта нет, а поскольку код класса выполняется в строгом режиме, `this` становится `undefined`. Исправить это можно привязкой контекста через `bind` (`keyboard.describe.bind(keyboard)`) или обёртыванием вызова в стрелочную функцию.

4. **Чем приватное поле `#items` отличается от обычного свойства `_items`?**
   Нижнее подчёркивание `_items` — это просто договорённость между программистами, само свойство остаётся открытым и его можно изменить снаружи. Приватное поле `#items` защищено на уровне самого языка JavaScript: оно невидимо снаружи, не попадает в `Object.keys` и `JSON.stringify`, а доступ к нему есть только внутри тела класса.

5. **Почему обращение к приватному полю снаружи класса это синтаксическая ошибка, а не ошибка выполнения?**
   Потому что движок JavaScript проверяет правила приватности ещё на этапе разбора (парсинга) кода, до запуска программы, и сразу запрещает выполнение такого файла.

6. **Чем статический метод отличается от обычного? Приведите пример, когда нужен статический метод.**
   Обычный метод вызывается у конкретного экземпляра объекта и работает с его данными через `this`. Статический метод (`static`) принадлежит самому классу и вызывается у класса (`Product.fromJSON(...)`). Он нужен для общих действий, не привязанных к конкретному экземпляру — например, для создания объекта из JSON-строки (`fromJSON`) или проверки принадлежности объекта классу (`Cart.isCart(obj)`).

7. **Почему вычисляемую сумму лучше делать геттером, а не хранить в поле?**
   Геттер вычисляет сумму заново при каждом обращении на основе актуальных цены и количества. Если хранить сумму в отдельном поле, при изменении количества товара сумма в поле «устареет» и станет неверной, если забыть её пересчитать вручную.

8. **Зачем в конструкторе наследника вызывать `super()` и почему до этого нельзя использовать `this`?**
   В классе-наследнике сам пустой объект создаётся конструктором родительского класса. Пока `super()` не вызван, объект ещё не создан, поэтому обращение к `this` до `super()` вызывает ошибку `ReferenceError`.

9. **Как движок находит метод при вызове `monitor.describe()`?**
   Сначала движок ищет `describe` среди собственных свойств самого объекта `monitor`. Не найдя его там, он переходит по скрытой ссылке в прототип `PhysicalProduct.prototype`, затем выше по цепочке в `Product.prototype`, находит метод там и вызывает его с `this === monitor`.

10. **Почему в `CartView` состояние нельзя менять напрямую, а только через `setState`?**
    При прямом изменении `this.state` данные в памяти обновятся, но метод `render()` не запустится, и интерфейс останется устаревшим. Метод `setState` не только создаёт новый объект состояния, но и автоматически вызывает перерисовку (`render()`).
