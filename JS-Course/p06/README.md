    1. Что выполнится раньше: return внутри try или код в finally? Почему?
Код в finally выполнится раньше возврата значения из функции. Инструкция return сначала вычисляет возвращаемое значение, затем управление передаётся в finally, и только после его завершения функция отдаёт результат.
2. Почему try..catch не перехватывает синтаксическую ошибку в самом файле скрипта?
Перед выполнением кода движок выполняет парсинг всего файла. Если в коде допущена синтаксическая ошибка, выполнение файла даже не начинается, поэтому блок try на этот момент ещё не существует. try..catch ловит только ошибки времени выполнения.
3. Зачем создавать собственные классы ошибок вместо new Error(текст)?
Собственные классы позволяют разделять ошибки по типам через оператор instanceof (вместо ненадёжной проверки текста сообщения), а также передавать в объекте ошибки дополнительные структурированные данные (например, имя поля формы или ID товара).
4. Как читать стек вызовов в err.stack? Что такое раскрутка стека?
Стек читается сверху вниз: самая верхняя строка указывает на место, где произошла ошибка, а строки ниже показывают цепочку вызовов функций, которые к ней привели. Раскрутка стека — это процесс, при котором движок после throw поочерёдно снимает записи о вызовах функций со стека, пропуская весь оставшийся код в них, пока не найдёт ближайший блок try..catch.
5. Что такое изоморфная обработка ошибок и чем «ошибка как значение» отличается от исключения?
Изоморфный код одинаково работает в разных окружениях (браузер, Node.js) и для разных типов функций. При подходе «ошибка как значение» функция не прерывает выполнение через throw («прыжок» по стеку), а возвращает ошибку как обычный элемент результата (например, массив [err, data] или объект { ok, value, error }), который проверяется обычным if.
6. Почему в new Date(2026, 8, 1) получается сентябрь? Что хранит объект Date внутри?
В JavaScript месяцы нумеруются с нуля (0 — январь, 8 — сентябрь). Внутри объект Date хранит одно число — количество миллисекунд, прошедших с начала эпохи Unix (1 января 1970 года 00:00:00 UTC).
7. Почему (1.005).toFixed(2) равно '1.00' и как правильно округлять деньги?
Из-за особенностей двоичной арифметики с плавающей точкой число 1.005 хранится в памяти как 1.0049999999999998934..., поэтому при округлении до сотых оно честно округляется вниз до 1.00. Правильный способ работы с деньгами — переводить суммы в целые копейки (предварительно отсекая погрешность через .toPrecision(15) и Math.round), вести все расчёты в целых числах и делить на 100 только при выводе.
8. Чем свойство-символ отличается от обычного свойства объекта?
Символ гарантированно уникален, поэтому исключает случайное перезаписывание чужих свойств. Кроме того, свойства с ключами-символами скрыты от стандартных механизмов перебора и сериализации: их игнорируют Object.keys(), цикл for..in и JSON.stringify().
9. Как устроен протокол итерации и что делает yield в генераторе?
Протокол итерации требует наличия у объекта метода [Symbol.iterator](), который возвращает объект-итератор с методом next(). Каждый вызов next() возвращает объект вида { value, done }. Оператор yield в функции-генераторе приостанавливает её выполнение, сохраняет текущее состояние (локальные переменные и позицию) и отдаёт очередное значение наружу до следующего вызова next().
10. Почему WeakMap и WeakSet нельзя перебрать и для чего они нужны?
Объекты в них хранятся по слабым ссылкам и удаляются сборщиком мусора в непредсказуемые моменты времени. Если бы их можно было перебирать или узнавать размер, результат зависел бы от того, успел ли отработать сборщик мусора. WeakSet используют для отметки объектов (например, «объект уже обработан»), а WeakMap — для кеширования и хранения служебных данных, привязанных к объектам, без риска утечек памяти
