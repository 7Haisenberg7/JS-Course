1. Что такое DOM и чем он отличается от исходного HTML-кода страницы?
DOM (Document Object Model) — это древовидная структура объектов в памяти браузера, которую он строит после разбора HTML. В отличие от статического текста исходного HTML-файла, DOM — это «живая» модель, которую можно изменять через JavaScript, и браузер сразу отобразит эти изменения на экране (именно текущее состояние DOM видно во вкладке Elements в DevTools).
2. Почему у <ul> с тремя <li> свойство childNodes.length больше трёх?
Потому что childNodes учитывает все типы узлов, включая текстовые (#text, тип 3), которыми являются пробелы и переносы строк между тегами в HTML-разметке. Чтобы получить только дочерние элементы-теги (тип 1), нужно использовать свойство children.
3. Чем живая коллекция отличается от статической? Какие методы возвращают какую?
	• Живая коллекция (HTMLCollection) не хранит список, а каждый раз заново запрашивает актуальное состояние DOM при обращении к ней (автоматически обновляется при добавлении/удалении элементов). Её возвращают методы getElementsByTagName, getElementsByClassName и свойство children.
	• Статическая коллекция (NodeList) — это «снимок» элементов на момент вызова метода, она не меняется при изменении страницы. Её возвращает querySelectorAll.
4. Чем textContent отличается от innerHTML? Что такое XSS?
textContent воспринимает переданную строку исключительно как обычный текст и отображает HTML-теги буквально (как символы). innerHTML парсит строку как HTML-разметку и создаёт новые DOM-элементы. XSS (Cross-Site Scripting) — это уязвимость, возникающая при вставке непроверенных пользовательских данных через innerHTML, когда злоумышленник передаёт вредоносный HTML-код (например, <img src=x onerror=alert(1)>), и браузер выполняет чужой JavaScript-код.
5. Чем атрибут href отличается от свойства href?
Атрибут (link.getAttribute('href')) возвращает ровно ту строку, которая написана в HTML-коде (например, #catalog). Свойство (link.href) возвращает полный, разрешённый браузером URL-адрес (например, http://127.0.0).
6. Почему append уже вставленного элемента перемещает его, а не копирует?
Каждый элемент в DOM — это уникальный объект в памяти браузера, и один узел не может одновременно находиться в двух местах дерева. При вызове append для существующего узла браузер сначала удаляет его со старого места и вставляет в новое. Для создания дубликата нужно явно вызвать el.cloneNode(true).
7. Зачем нужен DocumentFragment?
DocumentFragment — это лёгкий виртуальный контейнер вне основного DOM-дерева. Он нужен для пакетной вставки множества элементов за одну операцию: браузер пересчитывает геометрию страницы (reflow) и перерисовывает её один раз вместо перерисовки на каждый добавленный элемент.
8. Почему управлять оформлением лучше через classList, чем через style?
Использование classList разделяет ответственность: визуальное оформление остаётся в CSS-файлах, а JavaScript отвечает только за переключение логических состояний (классов вроде .active, .hidden, .selected). Прямое изменение style засоряет HTML инлайн-стилями с высоким приоритетом, которые трудно переопределить и поддерживать.
9. Что означает формула UI = f(state)? Какую проблему она решает?
Она означает, что интерфейс (UI) полностью вычисляется как функция от текущего состояния данных (state). Этот подход решает проблему рассинхронизации данных и интерфейса: разработчику больше не нужно вручную отслеживать и обновлять десятки разрозненных мест на странице после каждого действия пользователя.
10. Почему при полной перерисовке теряется фокус и как это решает обновление по ключу? Какая аналогия у этого в React?
При полной перерисовке старые DOM-узлы уничтожаются и заменяются новыми — вместе с ними исчезает внутреннее состояние элементов (фокус, положение курсора, выделение текста, скролл). Обновление по ключу сопоставляет элементы по уникальному идентификатору (id) и меняет в DOM только те свойства/узлы, которые реально изменились, не трогая остальные. В React эту задачу выполняет механизм Reconciliation (согласование) с использованием виртуального DOM и обязательного пропа key при рендеринге списков.
